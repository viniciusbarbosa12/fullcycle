# Lab Phase 8 - Observability

## Stack

- Prometheus collects Kong metrics every 15 seconds.
- Grafana Alloy discovers the lab containers through the Docker socket.
- Loki stores the container logs.
- Grafana provides a preconfigured dashboard for metrics and Kong logs.

## Run

The Phase 2 APIs and Phase 3 Kong must already be running on the external
`gateway-lab` network.

```bash
docker compose up -d
```

Open:

- Grafana: http://localhost:3000
- Prometheus: http://localhost:9090
- Loki readiness: http://localhost:3100/ready
- Alloy UI: http://localhost:12345

Grafana uses anonymous admin access only for this local lab. The dashboard is
available in the `Gateway Lab` folder as `Kong Gateway Observability`.

## Generate traffic

```bash
curl -H 'X-API-Key: gateway-lab-key' http://localhost:8000/orders
curl -u 'lab-user:lab-password' http://localhost:8000/customers
curl http://localhost:8000/orders
curl http://localhost:8000/customers
```

The successful requests produce `200` responses. The requests without
credentials produce `401` responses generated by Kong.

## Signals

Important Prometheus metrics:

- `kong_http_requests_total`: request count by route, status, and source.
- `kong_request_latency_ms`: total request latency.
- `kong_kong_latency_ms`: latency added by Kong and its plugins.
- `kong_upstream_latency_ms`: latency waiting for the upstream API.
- `kong_bandwidth_bytes`: ingress and egress volume.

The Loki query used by the dashboard is:

```logql
{job="docker-gateway-lab", container="gateway-phase-03-kong-1"} != "GET /metrics"
```

## Security note

All ports bind to `127.0.0.1` and are intended only for local study. Alloy reads
the Docker socket to discover container logs; access to that socket is highly
privileged and requires a hardened alternative in production.
