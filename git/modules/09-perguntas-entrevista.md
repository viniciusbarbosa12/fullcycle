# Classic interview and real work questions

At the end of the plan, you must be able to answer:

1. What's Gitflow??
2. When to use Gitflow?
3. When Gitflow can be exaggerated?
4. What's the difference between `main` and `develop`?
5. What is a feature branch?
6. What is a release branch?
7. What's a hotfix?
8. What is a signed commit?
9. Why use GPG?
10. What is Pull Request?
11. What a good PR needs to have?
12. What and branch protection?
13. What is Code Review?
14. What should I evaluate in a Code Review?
15. What is CODEOWNERS??
16. What's Without?
17. What's the difference between major, minor and patch?
18. What's breaking change?
19. What are Conventional Commits?
20. What's the difference between `feat`, `fix`, `chore`, `refactor` and `docs`?
21. What is commitlint for??
22. What is Commitizen for?
23. How this flow helps in CI/CD?
24. How this flow improves quality on big teams?

## How to Train

For each question:

1. Answer out loud without consulting.
2. Write a short answer.
3. Create a real example.
4. Explain the risk of not applying this concept.
5. Ask for review of your answer.
